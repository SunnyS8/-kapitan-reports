# Kapitan Reports

Веб-инструмент для отдела продаж и руководителя, который работает с выгрузками из 1С.

Проект собирает данные из Excel-файлов в единое рабочее пространство. Вместо нескольких таблиц и ручных расчётов пользователь получает отчёты по продажам, складу, оплатам и клиентам.

## Какие задачи решает

- помогает быстро оценить продажи за выбранный период;
- показывает разницу между планом и фактом;
- помогает найти неликвидные позиции и задолженности;
- собирает информацию о клиентах и документах в одном месте;
- позволяет повторно строить отчёты после загрузки новой выгрузки.

## Стек

- **Backend:** FastAPI (Python)
- **Frontend:** Jinja2 + Bootstrap 5 + Chart.js
- **Данные:** pandas + openpyxl (Excel-файлы 1С)
- **Деплой:** Render

## Возможности

### Отчёты по продажам
- Продажи по клиентам / товарам (сумма, кол-во, м², наценка)
- Динамика продаж по месяцам с разбивкой по категориям и топ-5 товаров
- План vs Факт (с уклонением, рекомендациями)
- Топ клиентов и товаров в разрезе номенклатуры

### Складской учёт
- Остатки на складах с сортировкой и группировкой
- Динамика по складу (приход/расход/остаток в шт и м²)
- Неликвиды по заданной формуле: цена × длина × ширина × рулоны

### Финансы
- Неоплаченные счета с автоматическим расчётом пени
- Задолженность клиента по каждому менеджеру

### Контакты и ЭДО
- Реестр клиентов с историей сделок
- Незавершённые ЭДО-документы

### Фильтрация
- Глобальный выбор диапазона дат на каждой странице
- Все отчёты обновляются при выборе периода

## Пользовательский сценарий

1. Пользователь загружает выгрузку из 1С.
2. Приложение разбирает Excel-файлы и подготавливает данные.
3. Пользователь выбирает период и нужный раздел.
4. Отчёт строится в веб-интерфейсе и при необходимости экспортируется в Excel.

## Локальный запуск

```bash
pip install -r requirements.txt
cp .env.example .env      # заполнить под свою конфигурацию
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

## Настройка

Все параметры задаются переменными окружения — в коде нет ни путей,
ни названий компаний. Полный список — в [`.env.example`](.env.example).

| Переменная | Назначение |
|---|---|
| `DATA_DIR` | Каталог для загруженных и сформированных файлов |
| `BASE_KNOWLEDGE` | Куда складываются готовые отчёты |
| `INTERNAL_CLIENTS` | Внутренние контрагенты через `;` — исключаются из общих продаж |
| `INTERNAL_CLIENT_TAG` | Подпись для таких строк в отчётах |

### Про данные

Папка `inbox/` и все файлы `*.xlsx`, `*.xls`, `*.csv` игнорируются Git
намеренно: выгрузки из 1С содержат названия клиентов, суммы и артикулы,
а это коммерческая информация, которая не должна попадать в публичный
репозиторий.

Справочники тоже игнорируются — держите их локально или в Persistent Volume
и указывайте путь через `BASE_KNOWLEDGE`.

## Адаптация под другую компанию

Проект написан под конкретную предметку: рулонные материалы, формула
«цена × длина × ширина × рулоны». Для другой компании потребуется
поправить сопоставление колонок в `app/services/excel_parser.py` и формулы
в соответствующих `report_*.py`.

Что обычно меняется в первую очередь:

- названия и порядок колонок в выгрузке 1С;
- формула расчёта неликвидов (`report_nelikvid.py`);
- список внутренних контрагентов — теперь задаётся через `INTERNAL_CLIENTS`
  в `.env`, править код не нужно.

## Развертывание

Проект можно развернуть на [Render](https://render.com) через GitHub. Файлы выгрузок из 1С загружаются в `inbox/` через веб-интерфейс или напрямую в директорию при деплое.

## Для кого

- отделы продаж;
- руководители небольших компаний;
- торговые компании с выгрузками из 1С;
- команды, которым нужен собственный внутренний отчёт без сложной BI-системы.

Проект можно адаптировать под структуру данных конкретной компании: добавить отчёты, поля, фильтры и экспорт.
